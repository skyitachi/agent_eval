## 网页 replay 默认挂 llm_judge grader

用户要求：网页上点 replay 采集出的任务默认要带 `llm_judge`，否则只测成本/时间、显示 "not graded"。

改动（`internal/replay/manager.go`）：
- 新增 `DefaultGrader = "llm_judge"` 与 `DefaultGraderConfig()`（`input: "both"` + 默认 rubric）。
  用 `both` 是因为收集来的多是绑仓库的编码会话，最终答复常只是 "done"，diff 才是活。
- `Config` 新增 `Grader`/`GraderName`/`GraderConfig`。`NewManager` 里一次性归一化：
  空/`default` → llm_judge；`none`/`-`/`off` → 不挂 grader（测试走这条，保持离线）。
- `collect()` 增加 grader 参数，透传给 `session.Options.Grader*`。
- **凭证闸门**：`grader == DefaultGrader && !judgeAvailable(cfg)` 时降级为不挂 grader 并写日志，
  点名 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`。理由：挂一个连不上的 judge 会让每个 cell
  变 graded+failed，看起来像 agent 的锅；不挂只是回到「可测量不可判分」，且日志说清原因。
  `judgeAvailable` 会读 config 里的 `api_key_env`/`auth_token_env` 覆盖。

测试：
- `replay_test.go` 两个 Manager 与 `server/sessions_test.go` 的 Manager 都设 `Grader: "none"`
  （否则本机若有凭证会在测试里真打网络）。
- 新增 `TestAWebReplayCollectedTasksCarryTheDefaultJudge`（collect 后断言 type/input）与
  `TestTheManagerDefaultsToTheJudge`（NewManager 归一化，含 none 的负例）。
- `go test ./...` 全绿（含 tests e2e 13s）。

要点：`aeval collect` CLI 的默认仍是**不挂 grader**（README 那段不变）；只有网页 replay 的
`replay.Config` 默认走 judge。两者不是同一处默认。

## 新增 `aeval grade`：单独重判一个已记录的 task

用户要求「支持单独给某个 task 进行 grade」。落成**离线重判**：不重跑 agent，用 row 里已存的
`diff` / `answer` / `trace_json` 再跑一遍 grader，把结论写回那一行。

- 新包 `internal/regrade`：`One(ctx, st, runID, taskID, sample, Options)`。`Options{Dataset, Graders,
  Threshold}`；grader 默认取数据集里该 task 声明的，`--grader` 覆盖（采集来的 task 一个都没声明，正好靠它）。
- `store.GradeUpdate` + `(*Store).UpdateGrade`：**只写 verdict 那几列**（graded/passed/score/threshold/
  grades_json/error）。不整行 SaveAttempt —— tokens/耗时/花费是已退出进程的测量值，重判改它就是造假。
  `Error` 只在传指针时替换（nil = 不动）。
- `grader.Sandboxed{RequiresSandbox() bool}` + `grader.NeedsWorkspace(typ)`：pytest/command 实现它。
  离线重判**按名字拒绝**它们，而不是对着 nil sandbox 跑出一个被读成 agent 失败的 verdict。
  另给 `llm_judge` 的 `reference_file` 加了 nil sandbox 的明确报错（原来会 panic）。
- 复用 `grader.Context.DiffOverride`（这个字段之前**无调用方**，注释里就写着「for replaying a stored
  run without a live sandbox」）。`recordedAttempt` 从 `trace_json` 复原 attempt；trace 丢失（payload
  预算会先丢 trace）时把 `answer` 塞进 `Trace.Result.ResultText`，喂给 judge 的文本才是当初那份。
- `dataset.NameGraders` 导出：loader 与 regrade 共用同一套命名规则（单数用 type，多数 `type#i+1`）。
- 陈旧状态：跑失败过的 cell 的 error 里可能有 `grade: ...`，重判成功后 `withoutGradeNote` 把这段摘掉
  （只摘 runner 自己写的 `"; grade: "` 段），否则一行同时写着 passed 和 grade 报错。
- CLI `aeval grade --run --task(可重复) [--sample -1] [--dataset] [--grader/--grader-name/--grader-config]
  [--threshold] [--json]`。不给 `--task` 是 usage error（exit 2）——不在用户没点名时批量重判。
  输出「新 verdict + was: …」，并提示登记过的页面已过期，给出 `report --run <id>`（`--db` 非默认时带上）。

实测（拷一份 aeval.db 到 /tmp，不碰用户的库）：replay `dd415a7a0cde9c20` → run `4d92d2be…` 的两个
`3c11e6dc-p0/p1` 本来都是 graded=0；`--grader patch` 判 p0 通过（13 files changed），report payload
变成 graded 1 / passed 1 / ungraded 1。p1 没指定 grader 时报错点名 `--grader` 并提示 llm_judge。

测试：`internal/regrade` 9 条（含 trace 丢失回退、sample 选择、拒绝 pytest、未跑过的 cell、陈旧
`grade:` 注释、数据集搬走后点名路径）、store 3 条（只改 verdict / 不动 error / not-found 点名 db）、
grader 1 条（哪些 grader 需要工作区）、e2e 2 条（真 CLI：重判翻转后 report 计数跟着变、且 run 数仍为 1；
pytest 被拒 + 无 `--task` 退出码 2）。`go test ./...` 全绿（e2e 13s）。

**踩坑**：e2e 里用 `mock` agent + 输出 stream-json 的脚本时，`answer` 存的是脚本**整段 stdout**（mock 把
子进程 stdout 当成自己的 result 文本），exact_match 于是对不上 —— 换成 `echo done` 的纯文本脚本即可。
`output.expect_answer` 这个字段**至今没有消费方**（另一个已知缺口）。

## 网页上直接 grade（撤销「报告只读」）

用户拍板：**报告只读的承诺作废，页面上的 cell 可以被重新判分**。落成 `POST /r/{id}/grade`。

- `internal/report`：`GradeAction{URL,Token,Graders}` 与 `Notice{Severity,Head,Note}` 都放进
  **`RenderOptions`/`pageView`，不进 payload** —— 哈希不变量（哈希覆盖的字节 == `/r/{id}.json`）因此不破。
  横幅与按钮都在 `<main>` 之外/由 shell 渲染，client 每次 render 清空 `<main>` 也不会擦掉它们。
- 客户端：`GRADE` 读 `document.body.dataset.gradeUrl`；**没有这个属性就不画按钮、也不加那一列**
  —— 存成文件的报告（`report -o x.html`）还是纯文档，按钮在那儿只会是个不能用的东西。
  列数差异由浏览器探针断言（served 比 saved 多正好一列）。
- grader 选择：`auto`（数据集声明的，没有就用 llm_judge）/ `llm_judge` / `patch`。`auto` 是策略不是 grader，
  它对应采集来的 task「按一下要一个结论」的语义。服务端**按名字白名单**接受，其余拒绝并点名。
- 复用 `regrade.One` + `Options.Fallback`（新增）：fallback 只在任务自己没声明 grader 时生效，
  声明了就按声明的判 —— 否则同名两处判的是不同的问题。
- 无 judge 凭证时 `regrade` **先拒绝、不落库**（错误点名 `ANTHROPIC_API_KEY`），否则一个 harness 故障会被
  记成 agent 失败。
- 写路由的守卫沿用 session 页那三条：Host 可答、Origin 是本服务、启动时生成的 form token。报告读路由仍然不设防。
- 判完 303 回 `/r/{id}?graded=<task>&sample=<n>#tasks`；横幅**从行读回**，不信任 URL（crafted link 只能
  得到事实或什么都没有）。

**变异验证 8/8 抓到**（脚本 `/tmp/mutbak/mutate.py`，跑完已删）。第一轮 7/8，唯一 MISSED 是
「只有单归属 run 的报告能判」那条 —— 查下去发现 `gradeAction` 里 `if _, err := runOf(reg); err != nil`
**不可达**：`HandleReport` 是先 `Derive` 后 `gradeAction`，而 `Derive` 对 `kind=run` 已经
`requiredParam(...,"run")` 空即报错。**删掉这个死守卫**，让 `mode != ModeRun` 成为唯一守卫（把变异
靶点挪到它），第二轮 8/8。
→ 教训：**MISSED 不一定是测试弱，也可能是那段代码本来就走不到**；两种处理不一样（补测试 vs 删代码），
先读调用链再决定。
