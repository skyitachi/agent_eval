### 环境 / 工具要点（本项目特有）

- **本机 managed python 3.13.12 没有 pytest**，`command -v python3` 拿到的就是它。
  带 pytest 的解释器在 `/Users/skyitachi/.workbuddy/binaries/python/envs/default/bin/python`（pytest 8.4.1）。
  跑 pytest grader / e2e 必须 `AGENTEVAL_PYTHON=<该解释器>`。
  README 里因此写成 `AGENTEVAL_PYTHON="$(python3 -c 'import pytest, sys; print(sys.executable)')"` —— 探测失败会**显式报错**，
  而不是静默给出 0/3 这种看起来像「模型不行」的结果。
- **Go 的 `flag` 包在遇到第一个非 flag 参数后停止解析**：`aeval compare --db X <left> <right> --out Y`
  会把 `--out Y` 当位置参数 → 打印 usage 退出。必须 `flags 在前、位置参数在后`。

### 设计要点（跨会话应记住）

- **报告是「数据库的函数」**：渲染层只读持久化状态；HTML 内嵌 payload 与 `/api/runs/{id}` 返回的 JSON
  由同一路径产出，有测试守住逐字节一致。
- **`neutralize()` 是 XSS 不变量**：把 payload 里 `<` `>` `&` 重写为 `\u003c` 等，封死 `</script>`、`<!--` 与开标签三种逃逸。
- **体积预算降级有优先级**：先丢通过项的 detail，失败/出错的 cell 保留证据最久，每次降级记入 `Warnings`。
- **退出码语义**：`0` 成功 / `1` 操作失败 / `2` 命令行错误 / `130` 中断；**有任务失败 ≠ 命令失败**（否则 CI 里没法用）。
- **配置就地解码进 `engine.Config`**，不建镜像结构；`KnownFields(true)` 严格拒绝拼错的键；
  时长必须带单位（yaml.v3 原生支持 `10m` / `1h30m`）。

### 追加：外部基准的数据格式调研 + 本项目「约定 vs 强制」的边界

调研结论（用于后续对齐格式，勿凭印象重述）：

- **SWE-bench 是「记录式」**：从 12 个热门 Python 仓库的真实 PR 反向挖掘，实例是一条条
  结构化记录（HuggingFace parquet），字段 `instance_id / repo / base_commit / problem_statement /
  hints_text / patch(gold) / test_patch / FAIL_TO_PASS / PASS_TO_PASS / version /
  environment_setup_commit / created_at / difficulty(仅 Verified)`。
  关键机制是**跑测试定基线**：在 base_commit 上先跑一遍，得出 FAIL_TO_PASS（补丁前失败、后通过）
  与 PASS_TO_PASS（前后都过）。`created_at` 用于防数据污染。变体：Lite 534 / Verified 500 /
  Multimodal / Multilingual。**没有目录结构，全是字段。**
- **Terminal-Bench 是「目录即任务」**：手写 + 人工验证，每个任务一个自包含目录
  `task.yaml`（instruction、difficulty、category、tags、parser_name、超时）+ `Dockerfile`
  或 `docker-compose.yaml` + `tests/test_*.py` + `run-tests.sh` + `solution.sh|solution.yaml`。
  核心是 **end-state verification**：不看 transcript，只看容器跑完后的环境状态；
  参考解只为证明任务可解，不参与打分。工作目录 `/app`，每任务一个镜像。
- 对照：SWE-bench 的「记录」更像本项目的 TaskSpec 全集（含 oracle 字段），
  Terminal-Bench 的「目录」更像本项目 dataset 目录；两家的 oracle 字段（gold patch /
  solution）在本项目对应 `metadata`（自由 provenance，引擎从不解释）。

本项目格式的**强制 vs 约定**（据 `internal/dataset/spec.go` + `loader.go` 实证）：

- 唯一被硬编码查找的文件名只有 `dataset.yaml` / `dataset.yml`（loader.go Load()）。
- **`tasks_file` 可选**：Manifest 有内联 `Tasks []TaskSpec`，loader 把内联与文件结果 append；
  两者都空才报 `declares no tasks`。→ 小数据集可以只有一份 dataset.yaml。
- **`prompt_file` 可选**：`resolvePrompt` 里 `Prompt != "" || PromptFile == ""` 就走内联 Prompt。
  → prompt 可直接写进 tasks.jsonl，`prompts/` 目录纯属惯例。
- **`workspaces/` 可选**：workspace.type 默认 `empty`；`files` 可用内联 `files` map 或 `assets`
  目录（二选一即可，Validate 要求至少一个）；`git` 用 repo+ref。
- **目录名 `prompts/` `workspaces/` `grades/` 全是惯例**：Assets / PromptFile / grader 的
  `suite` 都是任意相对路径字符串，代码里没有任何地方按名字匹配。
- **`dataset_hash` 的边界（值得记住的坑）**：`computeHash` 只把**解析后的内容**入 hash ——
  `ResolvedPrompt`（已读进来）与 `Workspace.Files`（字面量 map）算内容；但
  **`Workspace.Assets` 只进了一个路径字符串，该目录里文件的实际内容不入 hash**。
  也就是直接改 `workspaces/<task>/xxx.py` 不会改 `dataset_hash`，而输入确实变了。
  同类情形：`grades/` 下隐藏套件的改动同样不入 hash。若要做「hash 即输入指纹」的强保证，
  这两处需要补内容摘要。**尚未修改代码，仅在等用户决定。**

### 追加：真实仓库评测设计方案（`docs/real-repo-eval.md`，336 行）

用户要「在真实仓库 + 一段 prompt 上评测 agent」。先通读 `grader/pytest.go`、`grader/patch.go`、
`sandbox/workspace.go`、`sandbox/local.go`、`sandbox/docker.go`、`engine/engine.go`、
`engine/backend.go` 做实况盘点，再写设计。**只写设计，未动代码。**

**盘点结论：链路是通的，判分语义是浅的。**

已在代码里确认可用：`workspace.git`（repo/ref/subdir）、**默认剥离上游 `.git` 防抄答案**、
`setup` 后 re-baseline、隐藏套件 `pytest.suite`、`patch.forbid_changed_paths`、
`max_diff_lines` 等形状约束、docker 隔离、`--resume`。

P0 缺口三项：

1. **pytest 无语例级期望** —— `pytestConfig` 只有 `paths` + `min_passed`/`max_failed`；
   缺 `tests: [node_id]` 的「全过」语义、缺 FAIL_TO_PASS / PASS_TO_PASS 两组清单、
   缺 JUnit XML 逐用例解析（现在 `ParsePytestOutput` 只正则抓末尾汇总行）。
2. **无 `restore_paths`** —— 只有事后否决，没有评测前 `git checkout <baseline> -- <paths>`
   还原测试文件。文档里列了 `forbid` vs `restore` 的对比表（服从性 vs 能力）。
   `Baseline.SHA` 已存在，拿得到。
3. **无 `oracle` 字段 + 无 `aeval verify`** —— 参考解只能进 `metadata`（引擎不解释）。
   任务自检三检（可解性 / 必要性 / 稳定性）是数据质量的根。

另记两条设计判断：

- **网络与 setup 的张力**：docker 默认 `network:none`（`backend.go:99-102`），但 `workspace.setup`
  在沙箱内执行 → 装不了依赖。出路是「依赖烘进镜像」，让 `none` 真正成立（而不是开 bridge 放 agent 上网）。
- **`ref` 必须是 SHA 不能是分支名**：`materializeGit` 对分支走 `--depth 1 --branch`、对 SHA 走全量
  clone 再 checkout；只有 SHA 可复现，而「两次运行可比」是框架的核心承诺。

有效性威胁清单（答案泄漏面 6 条 + 作弊面 + 不可复现面）、规模成本表、P0/P1/P2 能力清单、
