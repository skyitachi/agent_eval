# 2026-10-13

## 「如何还原 agent 运行时的现场」——素材勘察（未动手实现）

起因：继 `--workspace-cwd` 只能绑 branch 现状之后，问「有没有更好的还原现场的办法」。

### 实测结论（本机 80 个转录）

**现场是三个不同的东西**：起点（会话开始时 agent 看到什么）、过程（改了什么）、环境（shell/变量）。
现在 aeval 只把起点记成 `cwd`+`git_branch` 一句话，过程只记 `EditedFiles`，环境零记录。

四类可用素材（多数未接入）：

1. **`session_context.gitStatus` attachment** —— 会话开始的 git 现场：branch、`Recent commits`、
   **脏文件清单**（`M .workbuddy/memory/2026-10-12.md` 这种）。`grep gitStatus` = **0 引用**。
   修正了前一轮的判断「脏改动完全无法复原」：**哪些文件脏**是可得；**内容**不可得（只有状态码）。
2. **Write/Edit/MultiEdit/NotebookEdit 的完整 input** —— 实测会话 `0f39688e`（改
   `~/.config/zed/settings.json` 三次）：
   - 默认 `--split session` 采集 → **0 个 Edit**（编辑发生在后 3 个 prompt 里，被 SplitSession 丢了）
   - `--split turn` → p2/p3/p4 各带一个 Edit，keys = `[replace_all, file_path, old_string, new_string]`
   - **aeval 已经把它存进 `BaselineToolCall.Input`（json.RawMessage，无截断）**
   → 「按序 apply 重建会话结束时的树」是**离线、零额外采集**能做到的。`old_string` 是天然校验锚点。
   盲区：Bash 副作用（`cat >`/`mv`/`rm`/包管理器）与 Read 过的文件（input 只有参数，result 不在其中）。
3. **`~/.claude/file-history/<session-uuid>/<sha256(absPath)[:16]>@vN`** —— 未文档化的逐版完整快照。
   **反推验证了命名**：`sha256('/Users/skyitachi/.config/zed/settings.json')[:16] == 'aad7ce0b9f3d1014'`
   正好是文件名前缀。`@v1` = 编辑前原文，`@v1→@v4` 的三步 diff 与转录里三次 Edit 的 old/new
   **逐步吻合** → 可作第 2 类的独立校验。aeval 现在只读 `TrackedFileBackups` 的 **keys**（填
   `EditedFiles`），values 指向的备份内容没读。局限：本机只剩 1 个会话目录（有 `.last-cleanup`），
   且只有 Write/Edit 触发的文件有。
4. **`~/.claude/shell-snapshots/snapshot-<shell>-<ts>-<rand>.sh`** —— 227KB 的 shell 环境快照，时间戳
   与会话对得上。0 引用。另外 `environment` attachment 给 cwd/isWorktree/isGitRepo/platform/shell。

### 忠实度排序（给用户的结论）

显式给予（`--assets` / `workspace.git` 钉 commit） > **baseline 重放**（覆盖 Write/Edit，缺 Bash）
> `--workspace-cwd` 绑 branch 现状 > 空工作区。

推荐的最小实现：`workspace: {type: replay}` —— 从 baseline 里的 tool 调用按序 apply，报告披露覆盖率
（`replayed N of M edits; K bash calls not replayed`）。用户未表态是否动手。

### 顺带的作用域说明

1. **`EditedFiles` 只在会话级切片输出**：`editedFiles()` 有 `len(turns) != len(s.Turns) → nil` 的早退，
   所以 `--split turn` 采集出来的每个任务都是 `edited_files: null`（实测确认），文件信息只能从
   tool calls 的 `file_path` 拿。这也是「某个文件被谁改的」在 turn 级切片上不可得的根因。
2. **`EditedFiles` 不落报告**：`grep edited_files internal/report/ cmd/` = 0 引用，只在 baseline 文档里。
