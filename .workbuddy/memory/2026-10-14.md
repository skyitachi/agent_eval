## 就地回放（`workspace.type: inplace`）收尾：披露 + e2e + 文档

接上一窗口的实现，本窗口做完 Task #5「补测试与文档」，并补了一个之前漏掉的设计缺口。

### 补的设计缺口：就地回放必须在报告里可见

**问题**：inplace cell 的 patch 和「harness 造的干净检出」里的 patch **长得一模一样**，而且目录在
跑完之后被还原了 —— 所以任何一行 cell 都**事后无法推出**这件事。CLI 在 run 时打了 `inplaceNotice`，
但 `report` 是「数据库的函数」：从 db 重生一份报告，这个事实就没了。

这和 v4（`agent_spec_json`）、v5（`chain_sessions`）是**同一类**问题，所以照同一套办了：

- **schema v6** `runs.inplace_tasks INTEGER NOT NULL DEFAULT 0` —— **计数不是 flag**，因为
  `--workspace-cwd` 只绑「有起点记录」的那些任务，一次 run 可以「一半就地」。
  默认值 0 就是答案（写 v5 那版代码根本做不到这件事），所以不需要 `unknown` 分支。
- `runner.inplaceTasks(ds)` 从 dataset 数（**不是从 planned cells**：`CreateRun` 发生在 `plan()` 之前，
  而且 samples 相乘后「cell 数」会读成「任务数」）。
- 报告头部 chip：`workspace <b>the recording's own directory</b>`。
- `comparisonWarnings` 加一条：`whether the cells ran in the recording's own directory (1 task vs 0 tasks)`
  —— 和 chain 那条并列，理由一样：两个 run 标签全同，但一个把用户真实工作树交给了 agent。

### e2e：`TestCLIReplaysInPlaceAndPutsTheDirectoryBack`

夹具抽成 `newInplaceFixture`（被渲染测试复用），六步：

1. 真 git 仓库提交一次 → `aeval hook start`（`AEVAL_HOME` 指向临时目录）→ 断言 hook 输出点了
   sid / commit 前 12 位 / 目录 / 存储位置。
2. `collect --workspace-cwd` → `tasks.jsonl` 里 `workspace.type: inplace`、`dir`=仓库、`ref`=记录的
   commit、`session` 保留、`output.type: patch`；`validate` 过。
3. `run` → patch 落库且含 `handoff.txt`；`inplace_tasks == 1`；目录 `HEAD` 回到记录 commit、
   `status --porcelain` 空、`calc.py` 内容还原、agent 建的文件在
   `$AEVAL_HOME/discarded/<sid>/`、**`git stash list` 为空**。
4. dirty 之后重跑 → **exit 0**（一次任务失败 ≠ 命令失败），cell 记 harness error，错误里点名
   `calc.py` / `uncommitted` / `no longer matches the state this replay starts from`；
   **用户的改动还在**（拒绝了就一个字节都不能动）。
5. `report --compare` 就地 vs 沙箱 → warnings 里出现「the recording's own directory」。

实测踩到两个 scratch 错误：`--run-id` 没写（默认是 UUID，`report --compare in-place` 找不到）；手写的
plain 数据集漏 `tasks_file:` 与 grader。
