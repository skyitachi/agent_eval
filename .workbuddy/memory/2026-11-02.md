## 修：report 页面点 grade 按钮没反应

**根因（前端，不是服务端）**：`app.js` 的 `gradeForm()` 用 `document.createElement('form')` 造表单后直接
`submit()`，**表单从未插入文档**。Blink 取消这次提交，只在 console 留一条
`Form submission canceled because the form is not connected` —— 无请求、无导航、无报错，页面就是不动。

**定位手法**：curl 手工 POST 同一路由返回 303 且写库成功（服务端无辜）→ 用 Node 22 原生 WebSocket 写了个
极简 CDP 驱动（`/tmp/click.js`：`PUT /json/new` 开标签页、监听 `Runtime.consoleAPICalled` /
`Network.requestWillBeSent` / `Page.frameNavigated`、`Runtime.evaluate` 里 `button.click()`），一条
console warning 就把案子结了。**注意 Chrome 新版 `/json/new` 只接受 PUT**，GET 会返回 "Using unsafe HTTP
verb"，且本机 curl 要走 `--noproxy '*'`。

**修复**：新增 `submitGrade(t, grader)` —— `appendChild(f)` 后再 `submit()`，1s 后清理（提交成功会导航走，
留不下垃圾）。两个调用点（表格行按钮、drawer 的 "Grade this cell"）都改走它。

**验证**：真浏览器复跑，`REQUEST POST .../grade body=csrf=...&task=4eb4178a-p0&sample=0&grader=patch` →
303 → 回页横幅 "The verdict on record is PASS. ... Reached by patch."。

**测试**：`tests/render_test.go` 的 `gradeProbe` 原来只断言「按钮和 picker 画出来了」。现在拦截
`HTMLFormElement.prototype.submit` 记录 `isConnected`/`method`/`action`/全部字段，**真的按下去**，
并验证 picker 选中的 grader 能带走。变异验证：把 `appendChild` 删掉 → 两条断言同时变红。

## 多轮判分的语义（结论，别再重新推一遍）

**没有"一个会话判一次"这回事，也没有对话历史回放。** 拆法是 session → turn(=task) → sample(=cell)：

- `--split session`（默认）：整个会话 = 1 个 task，只带**开头第一条 prompt**。
- `--split turn`：每个真人 prompt = 1 个 task，`Session` 相同、`PromptIndex` 记顺序。
- `--samples k`：task 跑 k 次 → k 个 cell。
- `--chain-sessions`：同会话的 task **共用一个 workspace 串行跑**，后一轮从上一轮留下的文件开始（只在
  `c.first` 时 materialise，runner.go:1184）；顺带强制 `Concurrency == 1`。

**判分粒度 = cell，且 baseline 是每个 cell 开跑前现取的**（runner.go:1195 `sandbox.CurrentBaseline` 在
`drive.Run` 之前）→ **chained 的第 k 轮 diff 是相对上一轮结束状态的增量，不是会话累计**。
`FinalAnswer()` = 该 attempt 的 `Trace.FinalText()`，**不含前几轮对话**；judge 的 `input: both` 也只有
本轮回答 + 本轮 diff（llm_judge.go:239 只有 final_answer/diff/both 三种，没有 trace 选项）。

所以：多轮在本框架里是**一串独立判定**，连续性只通过文件系统传递。抓「哪一轮引入回归」很合适；问「它在
第 3 轮还记不记得第 1 轮说过什么」永远做不到。中间轮默认也会各占一行 cell，用 `--min-prompt-runes` 或
`aeval grade --task` 收窄。

## `--grader-config-file`：让新采集的数据集自带 judge 配置

起因：`/replays/` 每次 replay 重建、web replay 走 `manager` 的 `DefaultGraderConfig()`（只有 input+rubric，
无 base_url/env 名）→ 新数据集不可判分，且给 yaml 手写的那段配置不会自动出现。

改动（4 个代码点）：
- `internal/dataset/grader_file.go`：`LoadGraderSpec(path)`。文件形状 = `GraderSpec`，但结构体只留
  `type/name/config`（`graderFile`），**weight/required/timeout_s 是未知键 → 报错**（两个读取方都会丢弃它们）。
  `KnownFields(true)`、空文件/无 type 各有专门错误、JSON 也能读（YAML 超集）。config **内部**的键不在这里校验，
  由 grader 自己的 `DecodeConfig` 兜（也是 DisallowUnknownFields）。
- `cmd/aeval`：`collect`/`serve` 各加 `--grader-config-file`。collect 与 `--grader/--grader-name/--grader-config`
  互斥（一个文件就是这三件事，共存时谁赢了另一个都读起来像是生效了）。serve 在 **listen 之前**解析
  （坏文件在它被点名的地方失败，而不是在花掉一次 agent run 的报告页上）。
- `serveJudge{spec,path}`：一个值同时喂 `replay.Config` 和启动横幅 —— 两者若能不一致，横幅就会宣称一个
  replay 并不使用的 judge。横幅实测：`judge     llm_judge (judge in …/examples/judge.yaml) attached to every replay task`。
- `examples/judge.yaml`：带注释的 DeepSeek 版本，`auth_token_env: DEEPSEEK_API_KEY` 只写变量名。

测试：loader 5 条（含 JSON、未知键、任务级键、空文件/无 type）；cmd 2 条（serveJudge 两个视图、collect 互斥）；
replay 1 条（manager 给的声明不被默认 rubric 覆盖，且落到 task.Graders）；e2e 1 条（真跑 collect → tasks.jsonl
四个键齐 + validate 通过 + 互斥退出非 0）。**4 个变异全部变红**：删 `KnownFields`、`replayConfig` 空转、
冲突检查写 `false`、collect 读了 spec 不用。

仍未做（用户未点头）：picker 里显式选 `llm_judge` 仍绕过数据集配置（`gradeSelection` 硬编码 DefaultGraderConfig）；
`aeval grade` 没有 `--grader-config-file`（只认 JSON）。

## judge 模型的默认值：deepseek-flash（并踩到 reasoning 预算坑）

`GET https://api.deepseek.com/models` 只列 **`deepseek-flash`**（DeepSeek-V4.1-Flash，1M 上下文）和
`deepseek-v4-pro`；**`deepseek-chat` 不在列表里但仍能答**（别名）。已把 `examples/judge.yaml` 与三个
`replays/*/dataset/dataset.yaml` 的 `model` 改成 `deepseek-flash`。

**真坑**：`deepseek-flash` 是 reasoning 模型，**思考块与回答共用 output budget**。同一份 6 kB judge prompt
（system 811 + user 6198）实测 thinking 长度 6.5k–25k 字符随机波动 → 默认 `max_tokens: 2048` 有一半概率
`stop_reason=max_tokens` 且 `content` 只有 thinking 块、无 text → judge 拿到空串 → 旧报错是
`no JSON object found; raw reply: `（把人引向解析 bug，实际是预算）。修法两层：

- 配置层：`max_tokens: 16384`（实测 2048 有时够、4096 反而被吃光、8192 勉强、16384 稳定）。
- 代码层：`llm_judge.Grade` 在 `resp.Text` 为空时先判 `StopReason=="max_tokens"` → 报
  `spent all N output tokens before writing an answer ... raise max_tokens`。判空的**不是**解析器。

验证：新文件 `internal/grader/llm_judge_test.go`（此前 judge **一个测试都没有**）两条 httptest 离线用例：
空文本+max_tokens 的报错措辞、`max_tokens` 配置真的上线（请求体里 16384）。变异（删守卫）→ 两条断言变红。
e2e：DB 副本 + 页面 `auto` → `judge_model=deepseek-flash`、score 0.75 pass、output 3800 tokens、23.8 s。
`collect --grader-config-file examples/judge.yaml` 产出的 tasks.jsonl 带 `model: deepseek-flash` + `max_tokens: 16384`，validate 通过。

**没改** `internal/llm/client.go` 的 `DefaultModel = "claude-sonnet-4-5"`：那是原生 Anthropic 的默认，改掉会让
官方 key 的机器打到不存在的模型。DeepSeek 的模型永远写进配置，不靠代码默认。

## grade 改成异步 + 成本落表 + 进行中状态

需求三件：HTTP 不再等判分、judge 花的 token 落表、页面能看出「正在判」。

**分层**：判定留在 attempt（报告照旧从它渲染），**请求**单独一张 `grade_jobs`（queued/running/done/failed）。
schema v10，只加表 → `upgradeV9ToV10` 是空函数（DDL 在 schema.sql，`CREATE TABLE IF NOT EXISTS` 先跑）。
**一个 cell 只能有一个活请求**靠部分唯一索引 `WHERE status IN ('queued','running')`，不是靠应用层判断
（`ActiveGradeJob` 只是礼貌的那一半，两键同时按下去由索引兜住）。

**拒绝仍在同步侧**：`regrade.Check` 先做 `planFor`（cell 没跑过 / 数据集搬了 / 要活工作区的 grader / judge 没
凭证），失败立刻 409 且页面还能解释；`Start` 落请求，`submit` 交给 worker，303 立刻返回。
提交后才会失败的只剩「判分本身」（模型空答、超时），那是这个请求的事实，正是 job 行要记的。

**进程死了的 running 行**由下次 `serve` 启动时 `AbandonGradeJobs` 收成 failed；停机走
`context.WithoutCancel` 才写得进去。worker 数 2，`WaitGrades(ctx)` 给测试和停机用。

**实测**：POST 23.8 s → **29 ms**；`grade_jobs` 一行 `deepseek-flash / in 147 / out 2132 / 13539 ms / score 0.68`；
横幅 `It cost 147 input and 2132 output tokens on deepseek-flash and took 13.5s.`；CLI 同样落表并打印
`judge  deepseek-flash: 1002 in / 7293 out tokens in 42.6s`。四个变异（不标 in-flight / 不汇总 token / 启动不回收 /
不设 meta refresh）全部变红。

## 坑：带 meta refresh 的页面不能被 --dump-dom 探针读

`TestReportGradeControlOnlyExistsOnAServedPage` 挂了 125 s 报 `signal: killed`，第一反应是 OOM
（本机 46 个 Chrome Helper、free 87 MB），**错了**：`pgrep` 那 46 个是用户真实浏览器的 Aperitif renderer，
不是测试实例；真正原因是探针页带了 `MetaRefresh: "3"` —— Chrome 每 3 秒重载一次，`--dump-dom` 等的
「加载完成」永远不会到来，2 分钟 context 超时把它 SIGKILL 掉。

修法两根：① 探针页不带 refresh（注释写明原因）；② 把「页面会不会让浏览器回来」下沉成 markup 断言
`internal/report.TestAPageCanAskTheBrowserToComeBack`（没有 refresh / content="3" / 间隔是选项 / 不改 payload）。
**教训**：`--dump-dom` 只能读会 settle 的页面；自我刷新页在浏览器测试里必须是「不测」或「测 markup」。

## 清理 headless Chrome 残留 profile（631 MB）

`tests/render_test.go:229` 的 `browserProbe()` 起系统 Chrome 时**不带 `--user-data-dir`**，Chrome 便落到
`~/Library/Application Support/Google/Chrome-headless/`，每次启动新建一个一次性 `scoped_dir<6位随机>/`。
干净退出会连目录一起删掉（实测连跑 3 次零新增）；被 SIGKILL（正是上面那条「自我刷新页把 2 分钟超时耗光」的
旧 bug）就整目录留下。所以残留目录里**只有 `.com.google.Chrome.*` 原子写临时文件、没有正式名**
（对照实验：自管 `--user-data-dir` 跑完只有正式名、零临时文件）。192 个目录 / 631 MB 已 `/bin/rm -rf` 清空，
根目录现在 0 项。

- 用户明确授权：这类临时垃圾默认直删，不再征询（已写进 user MEMORY.md）。
- 沙箱内 `rm` 报 `Operation not permitted`，真删必须 `dangerouslyDisableSandbox`。
- 未做的根治：给 `browserProbe` 加 `--user-data-dir=$(t.TempDir())`，可让每个探针实例互相隔离、并由 Go 回收。

## grade 按钮 409「no credentials」：声明没流到 grade，拒绝也不可行动

现场：页面点 grade（picker 默认 `auto`）→ 409 `grader "llm_judge" calls a language model and has no
credentials: set ANTHROPIC_API_KEY ...`。机器上有 DEEPSEEK_API_KEY（`~/.zshrc`，实测 /models 200）。

两个缺陷，一个是真的接线漏了，一个只是话说一半：

1. **`--grader-config-file` 只喂了 replay，没喂 grade。** `server.Options` 没有 judge 字段，
   `handleGrade` 的 Fallback 与 `gradeSelection("llm_judge")` 都硬编码 `replay.DefaultGraderConfig()`
   （无 base_url / 无 model / 无 env 名）→ 永远打 api.anthropic.com。也就是说「用 yaml 启动 serve」
   从来没让页面的 judge 打对端点。改动：`Options.Judge *dataset.GraderSpec` → `Server.judgeGrader()`
   （nil 时 `builtinJudge()`），picker 的 `llm_judge` 分支同源；serve 传 `judge.serverOptions()`，
   并允许 `--no-sessions` 与 `--grader-config-file` 共存（那条互斥原本的理由「只有会话页用它」已不成立）。
2. **拒绝文案不可行动。** 现在新增 `grader.Modelled` 能力接口（对称于已有的 `Sandboxed`）+ `NeedsModel()`，
   `checkUsable` 按能力判断而不是写死类型名；错误里点明**不调模型的替代**（`freeGraders()` = offline 且
   !NeedsModel，所以不会把刚失败的 judge 列成替代）和「网关要 base_url+model+自己的变量名」。
   另：serve 启动横幅在**无凭证时直接 warning**，不用等按按钮才知道。

验证：`TestTheJudgeAServerWasStartedWithIsTheJudgeItGradesWith`（httptest 桩断言 Authorization/model/path
是声明里的，`ANTHROPIC_*` 留空）；变异验证——把 `judgeGrader()` 改回硬编码，该测试立即失败。
真机端到端：`serve --grader-config-file examples/judge.yaml` → POST /r/55e6…/grade 303 →
`grade_jobs` done `deepseek-flash` 1299/1672 tok / 9.7s → 页面 `The verdict on record is PASS.` +
`It cost 1299 input and 1672 output tokens on deepseek-flash and took 9.7s.`

**注意**：我改的 serve 是本会话的后台任务（`--db aeval.db --addr 默认 18080`，DEEPSEEK_API_KEY 从
`~/.zshrc` 现取）。会话结束它可能消失，用户要长期跑得在自己终端重开同一条命令。

而 judge 卡片绿色 pass（它自己 config 的 0.67）。两套阈值各说各话，页面只画了后者。

   说明「为什么不是 1.0」（rubric judge 打分连续，0.8 才是"对但不完整"，1.0 量到的是 judge 的宽容度）。
   `aeval grade --help` 的 `else 1.0` 文案改成引用常量（原本硬编码，必然漂移）。
2. **task 级 `threshold`**：`dataset.TaskSpec.Threshold`（omitempty，0=未声明）、`EffectiveThreshold(fallback)`、
   进 `hashTask`（不同线=不同数据集）、校验 [0,1]。runner 调 `t.EffectiveThreshold(cfg.Threshold)` ——
   **task 压过 `--threshold`**（导入的 benchmark / judge 自带线，不能被命令行悄悄重算）。
3. **collect 写 judge 的线**：`grader.SelfThresholded{OwnThreshold(config)}` + `DeclaredThreshold(spec)`；
   `llm_judge` 用常量 `judgeThreshold=0.67`（和 Grade 里原来的 0.67 字面量合并，防漂移），`session.Collect`
   挂 grader 时写 `task.Threshold`。replay 走同一个 `session.Collect`，所以回放任务也自动带上。
   `examples/judge.yaml` 显式写了 `threshold: 0.67`。
4. **页面**：`verdictNotice` 增加 `graderCutoffs(a)`（读 `a.Grades[].Details["threshold"]`）+ `detailNumber`；
   app.js 的 grader 卡片加 `own cutoff` chip。措辞**刻意不写"score≥cutoff 所以 pass"**——实测重判给 0.65
   而 cutoff 0.67，卡片仍是 pass（模型断言 `passed:true` 时走 `*verdict.Passed && score >= threshold*0.5`）。
   顺手给 llm_judge 的 details 加 `model_passed`，让抽屉里能解释那个算术。

**重判沿用行上的阈值**（regrade 的既有语义，未改）：所以那次历史 cell 点按钮仍会看到 1.00→FAIL；
要在新线下看结论必须 `aeval grade ... --threshold 0.6`。这条写进了 README 中英两版。
