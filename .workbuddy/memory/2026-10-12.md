## gitignore：补两个真会漏出去的目录

起因是一个问题「判断哪些目录应该加到 gitignore 中」。做法是先把仓库里**每个**目录过一遍
（跟踪数 + 是否被忽略），再对每个候选问「它是产物还是源」。

**结论：只有两个缺口，都是真的。**

1. **`/workspaces/`（新加）** —— `runner.go:340-346`：`--work-root` 为空时 work root =
   `<数据库所在目录>/workspaces`，而默认库是仓库根的 `aeval.db` → **跑一次默认形态的评测
   就在仓库根建 `workspaces/`**。实测（在 /tmp 的仓库副本里按文档形态跑一次 `--keep`）：
   `workspaces/<runid>/<task>/s0/`，每个 cell 是目标仓库的完整拷贝，**内含一个嵌套 `.git`**。
   改动前 `git status` 是 `?? workspaces/`；更糟的是 `git add -A` 会把每个 s0 **当成 gitlink
   收进索引**（git 自己会警告 "adding embedded git repository"）—— 表层是噪音，实际是
   「clone 出来没有内容」的坏仓库。
2. **`/datasets/local_claude_code/`（新加）** —— `collect` 的产物，里面有本机绝对路径
   （`/Users/skyitachi/tmp/claude-code`）和真实会话原文，且随时可从会话重新生成。

**必须锚定根**：`datasets/demo/workspaces/` 是**被跟踪的数据集资产**（4 个源文件），写
`workspaces/` 会把它一起吃掉。`/reports/` 同理已经锚定，报告/site/work/workspaces 都在它下面。

**刻意不加的**：`datasets/mine/` 之类任意 collect 目录（那是猜命名，每加一个 `--out` 补一行）；
`*.db-journal` 一开始想跳过（WAL 模式下不会出现），但 `store.Open` **不检查 `journal_mode`
的返回值**，不支持共享内存的文件系统上会**静默回落**到 rollback 模式 → 还是加上了；`.workbuddy/`
（memory 是刻意跟踪的）。

**验证**：`git check-ignore` 逐条打了 16 个用例（含 3 条「必须不被忽略」的对照：demo 的
workspaces、`datasets/demo/tasks.jsonl`、`internal/store/store.go`），全对；并用
`git ls-files -i -c --exclude-standard` 确认**没有任何已跟踪文件被新规则误伤**。
